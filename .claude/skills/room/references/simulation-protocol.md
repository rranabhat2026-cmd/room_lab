# Probabilistic simulation protocol

Use this protocol for the required synthetic-data study. Choose a scientific data-generating process for the current question; do not reuse a generic simulator just because it is convenient.

## 1. State the purpose and estimand

Specify the question the simulation can answer: feasibility, parameter sensitivity, identifiability, statistical power, robustness, or experimental design. Define the quantity being estimated and the observational/experimental units. State which aspects of the real setting the simulation omits.

Define primary hypotheses, baselines, and decision criteria before inspecting outcomes. Do not keep changing assumptions until the proposed method wins.

## 2. Specify the generative model

Write the generative sequence or joint/conditional distribution, for example p(X, Y | theta). Define variables, units, support, transformations, relationships, and constraints. State physical conservation laws and their valid regimes when relevant.

Include relevant temporal, spatial, graph, or hierarchical structure. Model measurement noise, missingness, heterogeneity, confounding, censoring, or selection when consequential. Explain distributions and links: counts may require nonnegative integer distributions; bounded responses and rates need compatible supports. Treat these as modeling choices rather than universal defaults.

For transportation, distinguish infrastructure geometry, capacity, latent travel demand, and measured counts. Public network geometry may be real while generated demand is synthetic: label layers separately. Use abstract or aggregated locations for synthetic person-level records unless detailed locations are justified. Do not describe simulated demand as observed bicycle or vehicle activity.

## 3. Maintain a parameter registry

For each important parameter record:

| Field | Required content |
| --- | --- |
| Name and meaning | Symbol, definition, units, role |
| Distribution/value | Support, range, central value, dependencies |
| Provenance | Cited evidence, authorized-data estimate, or exploratory assumption |
| Source | URL/DOI and exact page/table, or explicit assumption rationale |
| Uncertainty | Range or prior and reason for its width |
| Sensitivity | Scenarios in which this parameter varies |

Use theoretical relationships and accessible aggregate evidence where possible. Do not claim calibration without a documented fitting target and actual estimation. If evidence is absent, label assumptions illustrative and broaden sensitivity analysis. Plausibility is not validation.

## 4. Build a reproducible experiment

Generate data through executable Python or R code with explicit random seeds and configuration. Record software/dependency versions, sample-size rationale, seeds, replication counts, and resource requirements. Give the execution command and expected output files.

Use fresh randomness across independent replications. Reuse the same simulated datasets across competing methods when appropriate for paired comparisons. Keep train/validation/test data and tuning separate. Fit preprocessing only on training data. Define graph, spatial, temporal, or grouped splits matching the intended extrapolation claim.

Start with a small diagnostic run, then run a justified number of replications and samples. Inspect supports, impossible values, missingness, dependence, dimensional consistency, conservation constraints, and seeds. Do not clip or discard failures silently. Record failure rates.

## 5. Evaluate mechanisms and methods fairly

Cover a central scenario and stress tests addressing the main threats; add favorable scenarios for context. Vary relevant noise, missingness, sample size, distribution shift, heterogeneity, and assumption violations.

Include a materially different or misspecified generating mechanism. Do not claim a physics-informed method is superior solely because the data were generated by its own exact governing equation.

Use credible simple statistical/mechanistic baselines and appropriate stronger baselines. Provide equivalent inputs, tuning opportunities, and comparison budgets. Distinguish implemented methods from proposed methods that were not run. Report failures and unfavorable results without omitting them.

Choose metrics tied to the estimand and practical goal. Use ablations to isolate the claimed mechanism. Quantify uncertainty across independent replications and report uncertainty in the generating assumptions separately. If estimating statistical power, simulate null and alternative conditions and inspect type-I error. Do not treat dependent rows as independent evidence or Monte Carlo replications as new real-world observations.

## 6. Label and interpret outputs

Attach this label to synthetic dataset metadata, captions, and result tables:

**Synthetic data — probabilistically simulated; no real participants.**

Use artificial record identifiers if needed. Do not include real personal records in the synthetic deliverable. If authorized empirical data are used for calibration, document that separate provenance; “synthetic” alone is not a privacy guarantee or a claim of differential privacy.

Mark result types explicitly: observed empirical finding, model prediction, theoretical deduction, simulated outcome, or untested hypothesis. State that simulation supports conclusions conditional on the assumed process and does not establish real-world predictive performance or validate the assumed process empirically.

## 7. Deliver artifacts and execution evidence

Provide the experiment script/notebook, configuration/parameter registry, synthetic dataset or representative sample, data dictionary with units, dependency information, result summaries, relevant figures, and a short run manifest.

Record in the manifest: executed/unexecuted/partial status, command, timestamp, environment, seeds, scenarios, replications, sample sizes, actual runtime when measured, checks performed, failures, and output locations. Identify all models actually run.

If computation is unavailable, produce runnable code and label it unexecuted. Give no invented numerical results or fabricated output paths. If only a small diagnostic simulation ran, report that exact scope and remaining experiments. Preserve negative findings and specify the next empirical validation step.
